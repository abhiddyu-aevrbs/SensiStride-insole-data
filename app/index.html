Connect over Bluetooth Low Energy in three steps

  1. Power the insole (USB or battery). The onboard LED shows it is running. The firmware advertises as DFU Insole.
  2. Use Google Chrome or Microsoft Edge on desktop, or Chrome on Android. Web Bluetooth is not available in Safari or Firefox.
  3. Click Connect below, choose DFU Insole in the browser dialog, and pair.

Help & Troubleshooting

Everything from flashing to pairing to fixing bad data

1. Requirements

  • A browser that supports Web Bluetooth: desktop Chrome or Edge, or Chrome on Android.
  • Safari, iOS, and Firefox are not supported — they do not implement Web Bluetooth.
  • The page must run in a secure context: open it from https://, from http://localhost, or directly as a local file in Chrome.

2. Running this app

Easiest reliable method — serve it on localhost from the project folder:

  • Open a terminal in the webapp folder.
  • Run python3 -m http.server 8000
  • Open http://localhost:8000 in Chrome.

For the competition you can also host the single index.html on GitHub Pages (HTTPS) and open it on any supported laptop.

3. Flashing the firmware

  • In the Arduino IDE: Tools → Manage Libraries, install ArduinoBLE (by Arduino).
  • Select board Arduino Nano 33 BLE, open DFU_Insole_BLE.ino, and upload.
  • After upload the board advertises as DFU Insole. The Serial Monitor (115200) mirrors readings for debugging.

4. Pairing problems

SymptomFix
Connect button does nothing / "Bluetooth not available"You are not on Chrome/Edge in a secure context. Switch browser or serve over localhost (see step 2).
"DFU Insole" not in the device listConfirm the board is powered and was flashed with the BLE firmware. Make sure no other phone/laptop is already connected to it (BLE allows one central at a time).
Pairs, then immediately disconnectsLow battery or USB brown-out. Try a different cable / fresh charge. Move closer to the laptop.
Connected but no data / all zerosSensors unplugged or not pressed. Press a sensor and watch the Live Monitor. If still flat, run the continuity tests in the build guide (Phase 7).

5. Data looks wrong

SymptomLikely cause
Two or more sensors read identical valuesA solder bridge or the old bare-rail short ties channels together. Re-run build-guide Phase 7, Test 1.
A channel is stuck at ~4095 or ~0Stuck high = signal shorted to 3.3V or no pull-down. Stuck low = open sensor or signal shorted to ground. Check that port’s wiring.
Values jump around wildlyLoose FSR joint or floating wire. Reflow the FSR tabs; confirm the pull-down resistor is seated.
Wrong sensor lights up when pressedA cord is in the wrong port. Match plug labels to ports: Ball→A1, Big Toe→A2, Heel→A3, Little Toe→A0.

6. Calibration tips

  • FSRs are not precision sensors — treat the values as relative pressure, not absolute force.
  • With no load, a channel should sit near 0–100 counts. Standing should drive the loaded zones well above the limit line.
  • Set the Limit slider on the Analysis tab just above resting noise so the risk flags are meaningful for your subject.

7. Safety & scope

This is a student research prototype for measuring plantar pressure patterns. It is not a medical device and must not be used for diagnosis or treatment decisions.
